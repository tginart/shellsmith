## Player

Build a usable `bench-runner` command in the designated project workspace, with source, tests, help, examples, and documentation. Choose the language and internal design. The product measures commands honestly; it need not optimize them, estimate hardware-independent speed, or match another benchmark tool's output.

- Support `bench-runner [--runs N] [--warmup W] [--export-json PATH] [--ignore-failure] COMMAND ...` and `--help`, with `--` available before command arguments. N defaults to 5 and is a positive decimal integer; W defaults to 0 and is a nonnegative decimal integer. Require at least one nonblank command. Each COMMAND is one argument containing shell command text, executed separately through the exposed shell/process interface; do not concatenate different commands. Validate options and counts before launching any command.
- In input order, perform exactly W warmup executions of each command, then exactly N measured executions, before advancing to the next command, unless failure aborts the session. Use the invocation working directory and inherited environment. Commands receive no interactive stdin. Drain or discard their stdout and stderr without allowing full output pipes to deadlock; runner stdout contains its own summary, not the benchmarked program's output.
- Measure each completed run with a monotonic clock from immediately before process launch until that process has terminated and been waited for. Include launch and shell overhead; do not subtract guessed calibration, fabricate samples, discard outliers, or replace elapsed times with requested sleep durations. Warmup timings never enter measured samples or statistics. Supply a testable timing/statistics boundary, while the actual CLI uses real command execution and elapsed measurements.
- Default behavior stops immediately on a nonzero command exit in either warmup or measured runs, exits nonzero, and identifies command, phase, iteration, and exit status on stderr. Do not report the session as complete or create or replace an export for an incomplete session. With `--ignore-failure`, continue nonzero normally exited commands and record every exit code; failed measured runs still count toward N and remain in the samples. Mark failure counts in the summary. Launch errors and signal termination remain fatal in either mode; explain these diagnostics. A completed ignored-failure session exits zero but must not portray its commands as all successful.
- For each completed command, report measured count, warmup count, failure counts, arithmetic mean, median, sample standard deviation, minimum, and maximum in seconds. For an even count median is the mean of the middle two sorted samples; standard deviation uses denominator N minus one, and is zero for N equal to one. Every measured sample is a finite nonnegative elapsed value. Human-readable rounding is allowed; exported samples retain measurement precision.
- JSON export is an object with `time_unit` equal to `seconds` and `results` in command input order. Each result contains `command`, `runs`, `warmup`, `times`, `exit_codes`, `warmup_exit_codes`, `mean`, `median`, `stddev`, `min`, and `max`. The times and measured exit-code arrays have N entries; warmup exit codes have W entries. Statistics are recomputable from the exported times, including samples from ignored failures. Only a completed session may write its export. Export I/O failure must produce nonzero status and an accurate diagnostic, not a success claim.

Test statistics using explicit known samples, including one sample and an even sample count. Separately execute harmless command fixtures that leave checkable invocation markers, establishing warmup and measurement counts, multiple-command order, spaced or quoted shell arguments, both failure modes, and abort-before-launch validation. Check the actual JSON against counts and recomputed statistics. Do not assert exact real durations or an absolute speed threshold; distinguish deterministic injected samples from real measured results. Document invocation, timing scope, units, failures, schema, and limitations from normal timing variability. Work only in task-local files. Finish with actual executed evidence and identify any unqualified runtime behavior.
